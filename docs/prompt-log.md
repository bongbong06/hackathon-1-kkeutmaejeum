## 1. 작성한 CLAUDE.md

### 어떤 규칙을 넣었나

배포된 템플릿을 바탕으로 하되, 작업하면서 실제로 문제가 될 것 같은 규칙 두 가지를 직접 추가했다.

**추가 1 — 브라우저 모달 금지**

```
- alert / confirm / prompt 등 브라우저 모달을 쓰지 않는다.
  확인과 오류 안내는 화면 안에 인라인으로 표시한다
```

왜 필요했나: 필수 요건에 "삭제 전 확인 절차"가 있어서 `confirm()`을 쓰는 게 가장 쉬웠다. 그런데 `confirm()`은 페이지 스크립트를 멈춰 세워서, 마지막에 브라우저로 전 기능을 눌러 검증하고 스크린샷을 뽑는 작업이 불가능해진다. 규칙으로 못 박아 두지 않으면 편한 쪽으로 흘러갈 것 같아 먼저 적었다.

**추가 2 — 비주얼 컨셉 섹션**

```
# 비주얼 컨셉
평원 위 구름 많은 맑은 하늘. 활동 1건 = 하늘 한 장.
활동명을 해시해 색조(H)를 정하고, 화면 카드와 영상 프레임이 같은 색을 쓴다.
```

왜 필요했나: 화면(CSS)과 영상(canvas)을 각각 만들다 보면 색 규칙이 따로 놀기 쉽다. 한 곳에 적어 두고 양쪽이 같은 값을 참조하게 했다.

### 작업 도중 바꾼 규칙

`외부 라이브러리: Chart.js (CDN)` → `없음 (canvas, MediaRecorder 등 브라우저 내장 API만 사용)`

왜 바꿨나: 처음에는 선택 기능으로 월별 통계 차트를 넣기로 하고 Chart.js를 적었다. 기획 중에 차트를 빼고 주간 리캡 영상으로 교체하면서 외부 의존성이 0이 됐다. 진행 상황 체크리스트의 선택 기능 3번도 같이 고쳤다.

### 결과가 기대와 달랐던 지점

CLAUDE.md는 나왔지만 "선택 기능"란이 비어 있었다. 어떤 기능을 만들지 내가 아직 안 정했기 때문이다. 또 "캡처해 달라"는 요청에 대해 무엇을 캡처하는지가 서로 달랐다 — 나는 작업 화면 전반을 생각했는데, 만들어진 답은 "브라우저 화면은 가능, Claude Code 터미널 화면은 불가능"이라는 구분이었다.

즉 **내가 무엇을 만들지 정하지 않은 채로 산출물을 먼저 요청한 게 문제**였다.

난 동아리라는게 꿈이라는 하나의 뜻으로 묶인다생각해서 좀 보면서 즐거웠으면좋겠어 회상이

```
디자인은 개인취향으로 평원에 구름이 많은 맑은 하늘 디자인으로잡고싶네
```

기능 목록을 나열하는 대신 **"이 앱이 어떤 느낌이어야 하는지"**를 말했다.

### 고친 뒤 무엇이 달라졌는지

같은 필수 기능인데 결과물이 달라졌다.

| | 처음 방향 | 고친 뒤 |
|---|---|---|
| 목록 | 표 형태 행 나열 | 세로 타임라인, 활동마다 다른 색 띠 |
| 저장 버튼 | `저장` | `이 날 기록하기` |

## 5. 오류 해결 사례 1건

### 발생한 오류

리캡 영상을 만들었는데 파일은 정상으로 보였다. 그런데 실제로 검사해 보니 길이가 맞지 않았다.

```
$ ffprobe -v error -show_entries format=duration,size \
    -show_entries stream=codec_name,width,height \
    -of default=noprint_wrappers=1 "recap-2026-W32.webm"

codec_name=vp8
width=1280
height=720
duration=3.178666      <-- 14초여야 하는데 3.18초
size=11841
```

표지 3초 + 활동 2건 × 4초 + 마무리 3초 = **14초**여야 하는데 **3.18초**로 잘려 있었다. 에러 메시지도 없고 파일도 정상 재생돼서 눈으로는 알 수 없었다.

### 원인 파악 과정

1. 파일이 깨진 건지 확인 — WebM 시그니처(`1a 45 df a3`)가 정상이었다. 파일 자체는 멀쩡했다
2. 녹화 중 화면 상태를 확인 — 진행률 문구가 `11초 남았어요`에서 20초가 지나도 그대로 멈춰 있었다
3. 그리기 루프를 의심 — 코드는 `requestAnimationFrame(tick)` 으로 다음 프레임을 예약하고 있었다
4. `requestAnimationFrame`은 **탭이 화면에 보이지 않거나 렌더러가 바쁘면 아예 호출되지 않는다.** 그리기가 멈추면 canvas가 바뀌지 않고, `captureStream`은 바뀐 화면만 내보내므로 녹화 스트림이 굶어버린다. 그동안 `MediaRecorder`는 받은 프레임이 없으니 영상 길이가 짧아진다

즉 **파일 문제가 아니라 프레임 공급이 끊긴 문제**였다.

### 해결 방법

그리기 루프를 `requestAnimationFrame` 에서 `setInterval` 로 바꿨다. `setInterval`도 백그라운드에서 느려지긴 하지만 완전히 멈추지는 않기 때문에 영상이 끝까지 만들어진다.

```js
// 바꾸기 전
function tick() {
  ...
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);

// 바꾼 뒤
const timer = setInterval(() => {
  const elapsed = (performance.now() - startedAt) / 1000;
  if (!drawAtTime(ctx, scenes, elapsed)) {
    clearInterval(timer);
    recorder.stop();
    return;
  }
  ...
}, 1000 / THEME.video.fps);
```

결과:

```
duration=13.029623     <-- 정상
size=155913            <-- 11KB -> 152KB
width=1280
height=720
```

### 이 과정에서 배운 점

**"돌아간다"와 "제대로 돌아간다"는 다르다.** 영상 파일이 만들어졌고 재생도 됐기 때문에 그냥 넘어갔으면 3초짜리 영상을 제출할 뻔했다. `ffprobe`로 길이를 실제로 재 보고 나서야 알았다.

그리고 브라우저 API는 **탭이 활성 상태라는 가정**을 깔고 있는 경우가 많다는 것도 알게 됐다. `requestAnimationFrame`은 화면을 부드럽게 그리는 용도지, 정해진 시간 동안 무언가를 진행시키는 용도가 아니었다.

## 6. 로컬 AI 모델 이미지 생성 (보고서 5장 재료)

### 원래 하려던 것

활동 내용을 로컬 오픈소스 이미지 생성 모델에 넣어 그날의 그림을 만들고, 그 이미지들을 주간 영상으로 합치려 했다. 로컬 환경은 이미 갖춰져 있었다.

### 왜 이번 제출물에 넣지 않았나

명세를 다시 확인해 보니 **로컬 모델을 금지하는 조항은 없었다.** 명세는 "별도 서버·DB 불필요"라고 썼을 뿐이고, "담당 교수 판단에 따라 기술 스택은 수업에서 다룬 것으로 대체할 수 있다"는 재량 조항도 있었다.

보류한 실제 이유는 두 가지다.

1. **재현성** — 제출물은 저장소 URL이고 강사가 클론해서 연다. 그 PC에 모델 가중치도 로컬 서버도 없으므로 해당 기능은 동작하지 않는다. 오픈소스인지 여부와 무관한 문제다
2. **시간** — 모델 서빙 + 프롬프트 설계 + 이미지 합성 + 웹앱 연동은 남은 구현 시간 안에 끝낼 수 있는 규모가 아니었다

### 어떻게 바꿨나

파이프라인(활동 → 이미지 → 주간 영상)과 결과물(주간 webm 1개)은 그대로 두고, **이미지를 만드는 주체만** 바꿨다.

| | 로컬 AI 모델 | canvas |
|---|---|---|
| 방식 | 활동 내용을 모델이 해석해 그림 | 좌표·색·글자를 지시해 그림 |
| 결과 | 매번 다름, 사진 같은 그림 | 매번 동일, 포스터 형태 |
| 필요한 것 | 모델 가중치, GPU, 로컬 서버 | 없음 (브라우저 내장) |
| 강사 PC에서 | 동작하지 않음 | 동작함 |

### 시간이 더 있었다면

`experiments/` 폴더를 따로 두고 로컬 모델 버전을 붙였을 것이다. 웹앱에서 활동 데이터를 JSON으로 내보내고, 로컬 스크립트가 그것을 읽어 이미지를 생성한 뒤 영상으로 합치는 구조라면 본체는 그대로 두고 부가 도구로 분리할 수 있다. 제출물의 재현성을 해치지 않으면서 원래 하려던 것도 보여줄 수 있는 형태다.
